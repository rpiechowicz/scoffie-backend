# Weekly Meals — audyt gotowości do Fazy 0 (agent AI)

## 1. Werdykt

Możesz wejść w Fazę 0 — ale najpierw ~pół dnia porządków, które nie są kodem agenta: (1) doprowadź lokalny stack do main i **załaduj tagi alergenów/diet** (dziś kolumn nie ma, a po deployu na niepustą bazę wszystkie 89 przepisów wyjdzie „czystych” — `conflictingAllergens()` zwróci `[]` dla kiełbasy), (2) napraw czerwony lint (CI od commitu 42c74e1 nie jest bramką), (3) zmerguj gałąź `docs/handover-windows-2026-08-28` — tam leży pełny plan Fazy 0, szerszy niż lista (a)–(e) (throttler, szkielet `src/agent/` z AI_ENABLED=false, 202+polling, catalogVersion, pomiar count_tokens, 3 otwarte decyzje). Twardy warunek na całą Fazę 0: **nic metered nie wychodzi bez tożsamości z tokenu na WS/JWT, limitera per użytkownik i trwałego ledgera użycia** — dziś WS bierze `userId` z payloadu, więc każdy klient spali cudzy budżet i przeczyta cudze preferencje. Reszta (walidacja WS, kontrakt błędów, brak `recipes:update`, pusta pula dla diet restrykcyjnych) to praca w Fazie 0, nie blokada startu.

Korekty do listy (a)–(e): (c) `recipes:update` nie istnieje w ogóle — trzeba go dodać, nie poprawić; (e) `getPreferencesForUsers` już jest na main (`src/users/users.service.ts:277`, ze spec) — brakuje tylko wystawienia agregatu z sylwetką i celami.
